# 🚀 Система умных уведомлений - Руководство пользователя

## 🎯 Что нового

Ваша система мониторинга теперь включает:

- **🔔 Гибкие правила уведомлений** с условиями и периодами отдыха
- **👥 Поддержка групп в Telegram** для командной работы  
- **🌐 Веб-интерфейс** для удобного управления правилами
- **🚫 Анти-спам защита** от повторяющихся уведомлений

## 🚀 Быстрый старт

### 1. Запуск системы
```bash
source .venv/bin/activate
python main.py
```

Система автоматически:
- Создаст базу правил уведомлений (`notifications.db`)
- Запустит веб-интерфейс на http://localhost:8090
- Создаст правила по умолчанию для ваших мониторов

### 2. Настройка Telegram бота для групп

**Добавление бота в группу:**
1. Создайте группу в Telegram
2. Добавьте вашего бота в группу
3. Отправьте команду `/add_group` (только для администраторов)
4. Бот подтвердит добавление группы в список уведомлений

**Команды администратора:**
- `/add_group` - добавить текущий чат в список уведомлений
- `/groups` - показать все авторизованные чаты

## 🌐 Веб-интерфейс управления

Откройте http://localhost:8090 в браузере для доступа к панели управления.

### Dashboard
- **Статистика**: количество правил, уведомлений за 24 часа, процент успешных отправок
- **Последние уведомления**: история недавних срабатываний

### Rules (Правила)
Управление правилами уведомлений:

**Типы условий:**
- `value_changed` - уведомлять при любом изменении
- `value_equals` - уведомлять при конкретном значении
- `value_contains` - уведомлять если значение содержит текст
- `value_unchanged` - уведомлять если значение не меняется X секунд
- `value_greater/less` - уведомлять при числовых сравнениях
- `custom` - собственные Python выражения

**Приоритеты:**
- 🔵 `low` - низкий
- 🟡 `medium` - средний
- 🟠 `high` - высокий
- 🔴 `critical` - критический

### Monitors
Текущее состояние всех мониторов:
- Текущее и предыдущее значения
- Время последнего изменения
- Длительность без изменений
- Количество активных cooldown'ов

### History
Полная история всех отправленных уведомлений с результатами доставки.

## 📝 Примеры правил

### 1. Уведомление об ошибках
```yaml
Название: Critical Status Alert
Условие: value_equals
Значение: error
Cooldown: 300 секунд
Шаблон: 🚨 Критическая ошибка в {monitor_name}: {new_value}
```

### 2. Уведомление о "зависании"
```yaml
Название: Status Stuck Alert
Условие: value_unchanged
Длительность: 3600 секунд (1 час)
Cooldown: 1800 секунд (30 минут)
Шаблон: ⚠️ {monitor_name} не изменяется уже {same_value_duration}
```

### 3. Числовые пороги
```yaml
Название: High Load Alert
Условие: value_greater
Значение: 80
Шаблон: 📈 Высокая нагрузка: {new_value}%
```

### 4. Пользовательское условие
```yaml
Название: Complex Rule
Условие: custom
Значение: new_value != old_value and 'error' in str(new_value).lower()
Шаблон: 🔍 Обнаружена ошибка: {new_value}
```

## 🛠️ Расширенные возможности

### Шаблоны сообщений

Доступные переменные:
- `{monitor_name}` - имя монитора
- `{db_name}` - имя базы данных
- `{old_value}` - предыдущее значение
- `{new_value}` - новое значение
- `{timestamp}` - время срабатывания
- `{same_value_duration}` - длительность без изменений

### Настройка целевых чатов

- `all` - отправлять во все авторизованные чаты
- `123456789,987654321` - конкретные ID чатов (через запятую)

### Тестирование правил

В веб-интерфейсе есть функция тестирования:
1. Создайте или редактируйте правило
2. Введите тестовые значения в секции "Test Rule"
3. Нажмите "Test Rule" чтобы увидеть результат

## 🔧 Конфигурация

Система автоматически создает правила по умолчанию для каждого монитора:

1. **Уведомление об изменениях** (cooldown: 1 минута)
2. **Уведомление о зависании** (если нет изменений 1 час, уведомлять каждые 30 минут)

Эти правила можно отключить или изменить через веб-интерфейс.

## 📊 API Endpoints

Система предоставляет REST API для интеграции:

- `GET /api/stats` - статистика
- `GET /api/rules` - список правил
- `POST /api/rules` - создание правила
- `PUT /api/rules/{id}` - обновление правила
- `DELETE /api/rules/{id}` - удаление правила
- `GET /api/history` - история уведомлений
- `GET /api/monitors` - состояние мониторов
- `POST /api/test-rule` - тестирование правила

## 🚨 Troubleshooting

### Веб-интерфейс не открывается
- Проверьте, что порт 8090 свободен
- Посмотрите логи на предмет ошибок запуска веб-сервера

### Уведомления не приходят
1. Проверьте в веб-интерфейсе History - отправлялись ли уведомления
2. Убедитесь что правила активны (зеленый статус)
3. Проверьте cooldown - возможно правило еще не готово к повторной отправке

### Telegram бот не отвечает
- Убедитесь что токен бота корректный
- Проверьте что чат добавлен в авторизованные (`/groups`)
